# Toolkit self-check contract

`tools/selfcheck.py` is repository-only (not shipped), Python 3.11+ standard library only. It accepts an optional repository root, defaults to its parent root, returns zero only when all checks pass, and prints sorted lines `PASS <check>: <detail>` or `FAIL <path>:<location> [<CODE>] <actionable-message>`. No expected failure emits a traceback.

## What a green self-check does and does not prove

A green run proves **structural and procedural necessity**: that the declared agents, skills, ownership registry and schema documents are present, internally consistent, and mutually parseable, and that every skill procedure *contains* the instructions the pipeline depends on.

It does **not** prove runtime conduct. The self-check cannot show that an agent invoked `.opencode/schema/validate.py`, acquired or classified a lock, updated `state.toml` through the compare-and-swap sequence, or obtained an independent review before closing a gate. `validate.py` itself cannot attest to any earlier invocation of itself: it inspects artifacts, not history. Validator wiring in a skill is therefore an **honor system** backed by evidence discipline, not runtime enforcement. Read the self-check as a necessary condition on the corpus, never as a sufficient condition on a run.

## Agents and permissions

The toolkit defines exactly **eight agents**, of which exactly one - `hal-coordinator` - is `mode: primary`; the other seven are subagents. Permission mappings are **heterogeneous** across those eight: there is no fixed permission key set. The frontmatter parser therefore accepts any nonempty permission mapping and compares it generically against the agent's own serialization, rather than asserting a per-agent key list. Earlier revisions of this document described only the original six-agent topology and a tester-only `read,grep,glob,list` extension; that is obsolete and must not be reintroduced.

## Frontmatter, links, fixtures and terminology

1. **`frontmatter`.** Parse the YAML frontmatter delimited by the first two `---` lines without third-party YAML. The supported subset is mappings, indentation, block scalars, and scalar strings. Skills (`*/SKILL.md`) require `name`, `description`, and `compatibility`; `compatibility` is `opencode`. Their tolerated top-level allowlist is exactly `name`, `description`, `compatibility`, `license`, `allowed-tools`. A skill's `name` must equal its containing directory name. Agents require `description`, `mode`, and `permission`; `mode` is `primary|subagent`, and `permission` is a nonempty mapping whose subkeys legitimately vary between agents. Their tolerated top-level allowlist is exactly `description`, `mode`, `permission`, `model`, `temperature`, `tools`, `name`. Reject malformed delimiters, duplicate keys, tabs, unsupported YAML constructs, wrong scalar/container type, missing common fields, empty descriptions, name/directory mismatch, and top-level fields outside the applicable allowlist.
2. **`links`.** Inspect relative Markdown links in the governed Markdown set. Strip fragments/query for filesystem resolution, URL-decode paths, ignore `http:`, `https:`, `mailto:`, and pure `#fragment`; require the target to be an existing regular file. Anchor existence is out of scope. Skip `.opencode/node_modules/`, `.opencode/package.json`, `.opencode/package-lock.json`, fixture payload Markdown, and generated/cache directories.
3. **`fixtures`.** Run the validator as a subprocess using the current interpreter. Every accepted root - `fixtures/valid/` and `fixtures/valid-multi-driver/` - must exit 0 and emit nothing. Discover bounded `fixtures/invalid/[0-9][0-9]-*/`, require at least the count **derived from** `tools/schema-fixtures.toml` rather than a literal this harness invented, run each with a 30-second timeout, and require exit 1 with a diagnostic **set** exactly equal to the `Expected diagnostic: <file>|<field>|<CODE>` lines in its README. Set, not multiset: the validator's `Reporter` deduplicates, so a repeated diagnostic is unobservable and a multiset assertion would be unimplementable. Exit 2 or timeout fails. Every code in the required-code list must be declared by at least one fixture, or the gate it names has never been shown to fire.
4. **`terminology`.** Use the baseline/scoping rules in `terminology.md` and reject only the exact tokens `type-state`, `Typestate`, `behaviour`, `normalise`, and `initialisation` in newly governed prose. Stage/identity shorthand is review-only, not mechanically asserted. A missing baseline fails with `[TERMINOLOGY_BASELINE_MISSING]`. Root `TODO.md` is exempt only while Git reports it untracked, because it is coordinator working state under active revision; once committed it is governed automatically, without editing an exemption list. When Git is unavailable, use a closed, non-wideable fallback containing only `TODO.md`.

### Governed Markdown discovery

The governed set is root `*.md` plus `.opencode/**/*.md`, extended by **exactly one** additional path, `docs/skill-template.md`, appended only when it exists. That file is toolkit-authoring material outside `.opencode/`, so it is named explicitly rather than by widening the walk to all of `docs/`. Only `links` and `terminology` consume this set; no new check was introduced for it, and no link to a nonexistent skill is permitted.

## Topology, ownership and contract checks

5. **`topology`.** Exactly eight agents exist and exactly one is primary.
6. **`contracts`.** Every agent's raw contract fence parses and conforms.
7. **`ownership`.** Every registry class in `.opencode/ownership.toml` is well-formed and claimed exactly once.
8. **`emissions`.** Each agent's `emits` declaration matches the AST-derived handoff-kind registry.
9. **`permissions`.** Each agent's permission statement matches its frontmatter serialization.
10. **`config`.** Root `opencode.json` parses and its default agent resolves to a primary agent.
11. **`dispatch`.** The dispatch policy is stated in `README.md` and `hal-coordinator`, and every specialist denies `task`.
12. **`roadmap-path`.** The exact roadmap path is named wherever a roadmap is referenced.
13. **`verdict`.** Coordinator and reviewer state the exact accepting verdict sentence with typed tokens.
14. **`commit-owner`.** `hal-integrator` is the sole commit owner and every other agent denies `git commit*`.
15. **`precedence`.** Every agent states the precedence sentence and its exact conflict ID set.
16. **`candidate-convention`.** `halucinator/test-candidates/` is used consistently and the hidden scratch convention is absent.
17. **`workflow-markers`.** Integrator and tester carry their required workflow headings and diagnostic keys.
18. **`skill-references`.** Every skill referenced in agent prose resolves to an existing skill.

## Skill-contract checks

These thirteen checks encode the authoring template in `docs/skill-template.md`. Each is invoked directly from `main()` and scans **every applicable discovered skill**: M4 deleted the two-generation exemption file `tools/skill-template-allowlist.tsv`, its parser, and the registry indirection that threaded a shared exclusion set into them, so there is no exemption mechanism and no file whose absence could silently narrow coverage.

Eleven of the thirteen are universal — their applicability class is every discovered skill, with no predicate. Two are not, and their applicability rule is a property of the skill, never a list of names:

| Check | Applies to | Why not universal |
|---|---|---|
| `skill-note-paths` | `generate-svd` and `generate-pac` only, derived from the emitted handoff kind `03-svd` or `04-pac` | Only these two stages write a first handoff note at a single deterministic path (`<documentation>/notes/SVD.md`, `<documentation>/notes/PAC.md`). The other stages have no such fixed first-note path, so there is no exact string to assert. The subject set is derived from each skill's parsed emitted kind and that kind is then mapped to its deterministic note; the mapping is never used to decide *whether* a discovered skill is in scope. |
| `skill-verdict` | every skill whose own contract fence declares the `independent-review` check | Only a skill gated on an accepting independent review has an accepting verdict to state. The set is **derived** from each skill's parsed `checks:` declaration, not listed: M4 shipped a hard-coded tuple that omitted `write-driver`, so the review gate it declares was never asserted and both accepting sentences could be deleted with the suite still green. Deriving the set closes that class of omission. A skill declaring the check is covered the moment it declares it; if the derived set is ever empty the check fails with `SKILL_VERDICT_NO_TARGETS` rather than passing vacuously. |

Where a check is not universal it is narrowed by an explicit, documented predicate — never by an exemption file, and never silently. A non-universal check still fails rather than passes when its applicability class turns out to be empty.

19. **`skill-contracts`.** Each discovered skill has exactly one raw ` ```halucinator-skill-contract ` fence immediately after its H1, with the required keys, the `checks` and `supplies-delta` grammar, and the single/repeatable key rules. A skill with no canonical contract mapping in `SKILL_SPEC` fails.
20. **`skill-emissions`.** The declared `emits` leaf set and `checks` set equal the sets derived from `validate.py` by `derive_registry()`.
21. **`skill-consumption`.** Every consumed leaf belongs to its declared predecessor kind, and the predecessor sets match the canonical mapping.
22. **`skill-structure`.** Ten exact nonempty H2 sections in order; a contiguous numbered `## Procedure` of imperative template verbs whose step 1 is the entry-recovery step, with at least as many steps as declared checks and every check named; an exact `## Validation` table; exactly three `## Exit criteria` predicate blocks; and an `## Application example` whose ` ```toml ` block is the emitted handoff using only that kind's schema leaves.
23. **`skill-trigger-frontmatter`.** Each description starts with `Use when`, contains `Wrong for`, and, for `scaffold-hal`, names its required dispatch terms.
24. **`skill-ownership`.** Each `writes` entry names the registry owner of that class; each `supplies-delta` entry names a semantic author who is *not* the registry owner.
25. **`skill-status-vocabulary`.** Parsed only from the raw contract's stage declaration and `## Exit criteria`, whose labels are only `ready`, `partial`, `blocked`; the nine legacy null sentinels are rejected only as TOML scalar values inside fenced TOML examples, never in ordinary prose.
26. **`skill-verdict`.** Every skill whose contract fence declares `independent-review` states the exact accepting verdict sentence and uses no spaced legacy verdict tokens. The gated set is derived from the parsed contracts, so declaring the check is what enrolls a skill.
27. **`skill-validator-wiring`.** Each skill names the validator command stem, the `--kind all` final gate, at least two validator placements inside `## Procedure`, and the honor-system limitation including that `validate.py` cannot attest to an earlier invocation.
28. **`skill-note-paths`.** For the two stages that have one — `generate-svd` and `generate-pac` — the deterministic note path appears exactly, with no soft alternative or default in the same paragraph.
29. **`schema-attribution`.** The schema documents attribute scope, decisions and foundation requirements to `hal-coordinator`, carry no stale architect phrasing, and state the corrected tester/integrator record attribution.
30. **`test-candidate-layout`.** `layout.md` ratifies the committed test-candidate root, its members, its ownership classes, the four `.gitattributes` lines and the `.run`-only ignore, and `README.md` no longer claims the ratification is deferred.
31. **`selfcheck-doc-parity`.** This document names every check the harness actually invokes, and carries the eight-agent and honor-system wording.

## Closure checks

These four checks guard the boundary and the shape of the skill set itself rather than the contents of one skill.

32. **`validation-guidance-isolation`.** Every Markdown file beneath the skill directory of each skill whose declared emitter is `hal-tester` — today `write-examples` and `debug-hardware`, derived rather than listed — including `SKILL.md`, all references, and the tester-safe profiles under `references/profiles/`, is scanned by a **bounded lexical tripwire**, in the same spirit as the two-token `DRIVER_API_LEAK` tripwire described in `.opencode/schema/06-driver.md`. A file fails with `VALIDATION_GUIDANCE_LEAK` when a relative Markdown link **resolves** beneath `.opencode/skills/write-driver/`, or when prose matches the thirteen-token implementation set (`pac::`, `unsafe {`, an `embassy-*/src/` or bare `*.rs` path, `read_volatile`/`write_volatile`, a `.read(|`/`.write(|`/`.modify(|` register closure, `OnDrop`, `WaitCell`, `waker.register`, `register_waker`). A scan that finds zero target files fails rather than passing vacuously, and at least one validation profile must exist or the guarantee is vacuous. The analyzer is a pure function of `(path, markdown)` self-tested against a conforming sample and seven near-misses, and against the real tester-facing validation references, which must survive the token set unchanged. The token set deliberately contains **no** `private|internal` word rule: that would match the legitimate disclaimer "not the target HAL's implementation or private state". **The check catches the named links and tokens and nothing else.** Semantic implementation guidance in plain prose — "write the control register, then enable its interrupt" — matches no token and passes. This is a tripwire against the cheap, mechanical leak, not a proof of isolation; human review remains the real boundary.
33. **`skill-discovery-closure`.** Every immediate child directory of `.opencode/skills/` contains exactly one regular `SKILL.md` — discovery globs `*/SKILL.md`, so a directory without one is invisible to every template check and is therefore a silent, undeclared exemption. The discovered directory set and the canonical skill mapping are compared **bidirectionally**, so neither a directory with no mapping nor a mapping with no directory can pass; M4's literal `M4_SKILLS` tuple is gone, and no literal name list narrows the comparison. The thirteen skills covered today are `debug-hardware`, `extract-hardware-facts`, `gather-documentation`, `generate-pac`, `generate-svd`, `integrate-interrupts`, `integrate-runtime-linker`, `review-artifact`, `scaffold-hal`, `write-clocks`, `write-dma`, `write-driver`, `write-examples`. Every discovered skill must be in scope for the template checks.
34. **`skill-platform-slices`.** The platform stage is a chain: three candidate slices followed by one final consolidator. Subjects are derived as every skill whose declared stage is `scaffold-hal` and whose parsed procedure role is not the final consolidator — never a literal name list. For each such slice the check asserts that its `ready` exit predicate says `ready` is unreachable, that its procedure contains `partial`, that the later slices consume `05-platform` while the first consumes `04-pac`, and that the runtime/linker slice states it is candidate-only and performs no independent canonical placement. It further asserts that only `scaffold-hal` carries the final **composite-evidence** and **canonical-placement** markers. Like every other check here this is **lexical**: it proves the corpus says a slice may not place canonically, never that a run refrained. A `05-platform` singleton replaced out of order, or a lock quietly dropped mid-chain, is invisible to it.
35. **`debug-lineage`.** Subjects are derived as every skill whose emitter is `hal-tester` and which both consumes and emits `07-tests`. For each, the emitted output filename template must differ from the consumed one, the procedure must require a fresh distinct name, the `## Application example`'s `handoff.inputs` must name a *different* `07-tests` path than the handoff it emits, and `tests.api_handoff` must name a `06-driver-*` path. A debugging run that pinned its own output as its own input, or that overwrote the preserved failing original, fails with `DEBUG_LINEAGE_SELF_REPLACEMENT`. The check reads templates and one worked example; it does not observe a real run, so it cannot prove a preserved original still exists on disk.

## M6 corpus, regeneration and runtime checks

These eleven checks were added by M6. Eight are pure corpus analyzers self-tested against in-memory near-misses; two drive a committed tool as a subprocess; one runs the interlock suite. They are invoked serially, so at most one build or test process runs at a time.

37. **`mcxa-example-boundary`.** Enforced by an **operative rule**, not by a table of literal current-to-replacement string pairs: no sentence may name an MCXA clock helper without example or optional-selection framing. A pair table would have to be hand-maintained for every rewording and would assert nothing about a twentieth sentence someone adds later. The check additionally requires every element of the minimum lifecycle contract - policy owner, acquisition or initialization, reset arbitration, lifetime accounting or its explicit absence, teardown or quiescence, frequency source or its irrelevance, and cancellation behavior - to be stated per resource. It proves corpus conformance only; whether an implementation actually routes policy through one owning layer is outside it.
38. **`error-clear-semantics`.** Rejects the "clear all error flags" mandate and the universal-snapshot wording, and requires the read-to-clear, W1C, W0C, preserve-control-or-unrelated and recoverable-latched terms. The W1C and W0C terms are required **group-wide across the six E4 files, not per file**: naming both conventions once in the corpus is what makes "cited read and clear semantics" actionable, and demanding both in every file would only produce ritual repetition. Corpus wording only; implementation is documented, not enforced.
39. **`target-first-driver-order`.** A heading and anchor-order analyzer asserting that the target capability inventory is written before any other target's implementation is opened, and that no MCXA implementation path appears before it. Corpus ordering only.
40. **`checkout-context-guard`.** Checks all eight agent copies of the E8 guard plus the root contract: the three classifications, TOOLKIT precedence over EMBASSY even when Embassy markers also appear, the ambiguity case, and the exact no-action sentence with no retry, lock, state publication, write or subdispatch. The existing `CONFIG_MISPLACED` rule remains. Corpus and config only; the runtime classification itself is documented.
41. **`install-no-overwrite`.** Parses each shipped install block and requires a destination-absent guard before every copy, with no force flag. Corpus text only; the user's actual execution is unproved.
42. **`reference-url-pins`.** Rejects moving evidentiary GitHub references - `main`, `master`, `HEAD` - in favor of an exact inspected commit URL. It proves pin immutability, not the legitimacy of what is pinned.
43. **`tester-destination-coverage`.** Parses the deny-then-reopen order of the A18 statement: schema 2 constrains `state.decisions.destination_crate` to a repository-root single segment `embassy-<vendor_id>`, which `embassy-*/**` covers, and the same statement must reopen the residual - bash, grep, filenames, diagnostics, history and tools remain leak paths. Enforces the configured path; overall blindness stays documented.
44. **`claim-truth-limit`.** Checks **disclosure only**. Every named file must state that a claimant may have fabricated execution evidence and that no external attester exists, and `validate.md` must carry the exact E6 one-hop deferral sentence. It ensures the limitation is disclosed; it does not detect a false claim and cannot.
45. **`citation-verification-corpus`.** A pure analyzer over the six E1 files: the v2 CitationRef leaves and the `sources.documents` binding are named; no agent-authored extraction path and no retired v1 leaf survives; the fail-closed remedy names `poppler-utils` and the exact rerun command; and anything describing the gate also states what it cannot prove, including semantic entailment. Corpus wording only - whether `validate.py` actually derives text from the pinned bytes is proved by the fixtures, not here.
46. **`fixture-regeneration`.** Runs `tools/generate_schema_fixtures.py --root . --check` and requires exit 0 with no output, so every committed fixture byte is declared by `tools/schema-fixtures.toml` and regenerates identically. This closes H10: source, generator and byte-identical regeneration are all in-tree. Check mode compares the generated set against **Git** - the union of the last commit and the index - as well as against the working tree, because a regeneration that stops emitting a file deletes it from the working tree and a worktree-only comparison would then find both sides agreeing it is absent. It proves **regeneration**, not that the declared mutations are the right ones; that judgement stays with review. It also cannot see a file deleted from the declaration and from Git in the same change, which is indistinguishable from a deliberate retirement.
47. **`runtime-protocol-tests`.** Requires `.opencode/schema/runtime.py` and `.opencode/schema/test_runtime.py` to exist, requires the suite to name `subprocess` so it drives the production helper black-box through files and exit codes rather than re-implementing the algorithm under test, requires the eight D17 faults to be named by some test, and runs the suite green with a bounded timeout. **Coverage here is derived from test names and docstrings.** It cannot prove that a test named for a fault actually injects it; a misnamed test is invisible to it. The real assurance is human review of `test_runtime.py`. Neither this check nor anything else in M6 closes the broker, cross-clone or physical-truth residuals.


## M6 compliance-review checks

The M6 compliance review returned **not-ready** and these six checks reproduce what it found. Three drive the interlock helper black-box through its CLI in throwaway directories and judge it by the files it leaves behind, not by what it reports about itself; three are corpus or coverage analyzers. Each is stated here with the limit its author declared, because a check that is read as proving more than it does is worse than no check.

48. **`no-invented-hardware-in-corpus`.** Scans the corpus for example hardware facts outside the fictional target. Its citation-subject half uses a **hand-maintained allowlist**, so it catches a named subject that is not on the list and nothing else: it cannot recognise a fabricated register offset, bit position or reset value, and it never will. Inventing a plausible hardware fact in prose remains invisible to every mechanical check here; that is why the rule is a hard rule and not a lint.
49. **`hardware-procedure-uses-interlock`.** Derives its subjects as the skills whose parsed contract emitter is the tester agent, and asserts that the target-affecting procedure names `acquire-board`, `before-board-op`, `begin-board-operation`, `complete-board-operation` and `release-board`, in that first-occurrence order, plus at least one recovery command. It asserts **procedure text and order, not behavior**: a procedure can name every command in the right order and an operator can still run a probe directly. An interlock the procedure needing it never calls is decoration, and this catches exactly that.
50. **`interlock-refuses-fabricated-evidence`.** Acquires a real interlock in a temporary directory, then hands the helper a recovery attempt and a SafeStateObservation whose FileRefs do not exist, and requires both to be refused, the lock never to record `board_state="safe"`, and release to be refused with the lock still on disk. This proves the helper **opens** the evidence it is handed. It cannot prove the evidence is true, that the six hazard observations describe the physical device, that the procedure is sufficient, or that any operator performed it.
51. **`interlock-override-requires-ambiguity`.** Requires `override-ambiguous-owner` to refuse an operator record that does not exist, and to refuse a lock the helper itself has just classified `live`. **It asserts only the two constructible refusals.** It does not prove the override correctly *accepts* a genuinely ambiguous owner - that case is covered by `test_runtime.py`, where the helper's own classification is driven to `ambiguous` and the heartbeat aged past the window - and nothing anywhere can check that the operator's confirmation of termination or physical isolation is true.
52. **`state-publish-is-atomic`.** Seeds an accepted `state.toml`, requires a stale generation to be refused **without touching the file**, and requires a matching generation to change the bytes and advance the generation by exactly one - asserted by reading the file, never from the command's own report of itself. A publish that writes nothing while reporting a matched CAS is worse than no publish, because every caller then believes its state is durable. This proves the write **happened**; it does not prove the write is crash-atomic, and durable cross-clone ordering stays deferred.
53. **`citation-path-tested`.** Runs `unittest discover` over `.opencode/schema/test_*.py` and requires a green suite naming all nine required citation cases: missing `pdftotext`, verifier timeout, PDF page error, Unicode/NFKC normalization, digit-safe hyphen joining, the interleaving gap bound, the bounded diagnostic payload, the **subprocess argument array**, and the **subprocess output bound**. The last two exist because the earlier suite injected an already-constructed failure at the `verify_citation` seam and never executed `run_pdftotext` at all, so a regression in command construction or exception translation would have passed everything. **Coverage is derived from test names and docstrings**, exactly as in `runtime-protocol-tests`: a test named for a case it does not exercise is invisible here, and nothing checks that the assertions inside are the right ones. The real assurance is a human reading `test_citation.py` and seeing that each case injects its fault.
54. **`interlock-recovery-can-reconnect`.** After `begin-board-recovery`, requires the helper to permit at least one recovery-scoped operation - `attach`, `reset` or `halt` - through an entry point it reads from the helper's own `--help`, while still refusing ordinary test operations (`run`, `load-ram`, `program-flash`) and still refusing release until recovery is verified. This exists because the circularity the owner ordered fixed once had **moved rather than gone**: entering recovery needed no evidence, but every operation an operator needs in order to find out whether the board is safe was then refused until recovery was already verified, leaving physical isolation or bypassing the helper as the only exits. A safety mechanism satisfiable only by going around it teaches operators to go around it. **It asserts reachability, not sufficiency.** It proves at least one recovery-scoped operation is permitted; it cannot judge whether the operations offered actually let an operator establish physical safety, and it cannot tell a correctly scoped authorisation from one so broad that recovery has become a general unlock. Reading which operations `RECOVERY_SCOPED_OPERATIONS` contains, and deciding whether that set is right, stays with review.


## Harness self-guards

This check constrains `tools/selfcheck.py` itself rather than the corpus it inspects.

36. **`skill-subject-derivation`.** Every skill-scoped check must select its subjects from `skill_paths(root)` discovery, so that adding or deleting a skill directory changes coverage automatically and no skill can be silently exempted by a literal in the harness. An AST analyzer over `tools/selfcheck.py` rejects four shapes: a literal skill-name comparison such as `name == "scaffold-hal"` (`SKILL_SUBJECT_LITERAL_NAME`); a literal skill-name collection used for filtering or equality (`SKILL_SUBJECT_LITERAL_COLLECTION`); a literal skill-directory root such as `".opencode/skills/write-examples"` (`SKILL_SUBJECT_LITERAL_PATH`); and mapping-key membership used as subject selection, such as `if n in SKILL_NOTE_PATHS` where the keys are skill names (`SKILL_SUBJECT_MAPPING_KEYS`). An expectation mapping keyed by skill name remains legitimate when the lookup happens *after* the discovered subject has already been selected and the mapping does not decide applicability. The analyzer matches these four syntactic shapes and nothing else: a subject set narrowed through an indirection it cannot follow — a helper returning a literal, or a name read from a data file — would pass while still being a literal list.

## No exemption mechanism

There is no allowlist. M3 carried one time-boxed, two-row exemption file so that two legacy driver skills could lag the template; M4 consolidated those two skills into `write-driver` and deleted the file, its parser, and the registry that distributed its parsed set. Deleting the data alone would have been unsafe — the parser failed **open to the empty set**, so a check pointed at a vanished file would have kept reporting `PASS` while asserting nothing. Data and parser therefore retired together, and the thirteen skill-contract checks above now take no exclusion set at all. `skill-discovery-closure` covers the one remaining way a skill could become silently exempt: never being discovered.

## Derivation and bounds

Registries are derived from source, not scraped from prose: `derive_registry()` walks `validate.py`'s AST to obtain the handoff kinds, their schema leaf paths and their canonical check IDs, and `invoked_check_names()` walks this harness's own AST to obtain the display name of every check `main()` invokes. Skill and agent contracts are parsed from raw Markdown fences so that a fenced example is never mistaken for a declaration. The structure and typed-example analyzers are pure functions driven by in-memory conforming and malformed near-miss fixtures, which is what proves they discriminate rather than rejecting everything.

The script skips `.opencode/node_modules/` completely and does not parse package JSON. Every filesystem walk is bounded to the repository, every subprocess to 30 seconds, and AST recursion, contract length and registry size to their declared maxima.
